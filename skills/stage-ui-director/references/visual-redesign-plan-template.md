# World Stage 视觉重做计划模板（v0.4）

这份模板用于把一次“地图/UI 看起来不够像产品”的重做，变成可复用、可回归、可扩展的生产流程。它只规定视觉投影、资产契约和验收方法，不改变世界事实、回放哈希或模型接入方式。

复制本文件到调用方工作区后，按 `{{...}}` 填写。没有对应项时写 `none`，不要凭空补故事或状态。

## 0. 计划元数据

```yaml
plan: visual-redesign
version: v0.4
worldId: "{{world-id}}"
sourceStage: "{{source-stage-path}}"
outputStage: "{{output-stage-path}}"
owner: "{{owner-or-agent}}"
startedAt: "{{iso-date}}"
baseCommit: "{{git-commit}}"
visualGoal: "{{一句话视觉目标}}"
```

### 目标声明

用一句可截图验证的话描述结果，例如：

> 让地图成为主要视觉区域，角色以统一的俯视/三分之四比例落在可行走地面上，侧栏只解释当前焦点，桌面和手机端都能完整读懂当前事件。

避免使用“更高级”“更精致”这类无法验收的形容词。

## 1. 输入冻结

在改代码前记录输入。所有路径必须来自当前工作区，不能把具体世界的事实写入通用 Skill。

### 1.1 必需输入

- **运行事实**：世界 manifest、回放快照、事件类型、时间步和稳定哈希；
- **当前 viewer**：可构建的 stage 目录、构建命令和离线启动命令；
- **视觉契约**：`style*.json`、`layout*.json`、scene、asset-manifest 和 animation-manifest；
- **目标视口**：至少 `1440x900`、`1280x800`、`390x844`，按项目需要追加平板或低高度视口；
- **参考证据**：当前版每个目标状态的截图和问题记录；
- **访问性信息**：可聚焦控件、键盘快捷键、语言、`prefers-reduced-motion` 行为。

### 1.2 输入快照

在计划目录中写入：

```text
visual-redesign-v04/
├── input/
│   ├── baseline.json              # commit、viewer、视口、回放哈希
│   ├── replay-facts.json          # T0…Tn 的可见事实摘要
│   ├── asset-inventory.json       # 资产路径、尺寸、哈希、回退
│   └── reference-notes.md         # 参考图只记录可执行特征
└── evidence/
    ├── before-1440x900-t0.png
    ├── before-1440x900-t3.png
    └── before-390x844-t3.png
```

基线截图只说明问题，不作为新的事实源。若基线无法重建，先修复构建/回放，再进入视觉重做。

## 2. 视觉目标与硬边界

### 2.1 先锁相机和比例

写入 `visuals/style.v0.4.json` 或等效契约：

- 相机：`top-down`、`orthographic-3/4` 或明确的其他单一投影；
- 场景画布最小可视比例（建议地图区域占桌面宽度 `>= 0.62`，窄屏占可用宽度 `>= 0.86`）；
- 角色 gameplay sprite 的目标屏幕高度、脚底锚点和阴影尺寸；
- 头像/立绘只允许出现在聚焦面板、对话详情或角色预览中；
- 路线、空间、交互点、事件和 HUD 的层级顺序；
- 安全区、面板最大宽度、气泡最大宽度和长文本换行策略。

统一比例前不要继续堆面板、渐变或动效。若现有图片只有正面立绘，必须在契约中标记为 `artDebt`，使用缩小的临时回退，不得直接把立绘当作地图角色。

### 2.2 视觉层级

推荐层级（由底到顶）：

1. 场景底图与道路；
2. 结构、遮挡和交互点；
3. 路线与移动反馈；
4. gameplay 角色、脚底阴影和状态标记；
5. 事件/对话气泡；
6. HUD、回放栏和聚焦抽屉；
7. 无障碍焦点环和错误诊断。

每个层级必须能回答“为什么现在显示”。没有对应回放事实的装饰不应进入默认视图。

## 3. 阶段计划与产物

每一阶段都要有输入、产物、出口。阶段可以在同一提交中完成，但不能跳过出口检查。

### P0 — 基线与回放冻结

**输入**：当前可构建 viewer、世界工作区、目标视口。

**产物**：基线截图矩阵、`baseline.json`、回放哈希、已知问题列表。

**出口**：T0、移动、对话、交换/决策、结尾至少各有一张截图；主线事实在重做前后哈希一致。

### P1 — 视觉契约与状态矩阵

**输入**：P0 证据、scene 和资产清单。

**产物**：`style.v0.4.json`、`layout.v0.4.json`、状态矩阵、组件层级图。

**出口**：每个可见组件都有目的、数据来源、显示条件、窄屏行为和回退；地图/角色/事件三个焦点模式的默认面板明确。

### P2 — 舞台壳层与响应式布局

**输入**：P1 契约。

**产物**：世界栏、地图容器、聚焦抽屉、回放栏、窄屏抽屉；不新增世界规则。

**出口**：桌面地图占主要面积；窄屏 `document.documentElement.scrollWidth <= innerWidth`；折叠面板后地图、标签和回放仍可用。

### P3 — 场景与角色比例

**输入**：P1 角色/场景契约、现有图片或程序化回退。

**产物**：场景分层、路线锚点、角色 gameplay sprite 或明确的回退标记、脚底阴影、遮挡排序。

**出口**：角色不漂浮、不被屋顶放大、不穿过关键遮挡；人物比例在 T0、移动、对话三个状态都稳定；缺图仍保留角色 ID 和位置。

### P4 — 事件可视反馈

**输入**：回放事件和 P2/P3 舞台。

**产物**：移动路线/抵达、对话停步/气泡、交换资源差异、决策结果、事件焦点高亮。

**出口**：每类事件至少一个可见反馈，反馈来自事件记录，不由 UI 猜测；切换时间步不会遗留上一步高亮。

### P5 — 截图回归与问题修复

**输入**：P0 基线、P4 viewer、固定运行 ID。

**产物**：after 截图、机器可读 `report.json`、重叠/截断/资源错误诊断、人工复核清单。

**出口**：所有硬失败为零；剩余风险逐项绑定视口、时间步、文件和修复建议。

### P6 — 发布与可扩展模板

**输入**：P5 报告、构建和审计结果。

**产物**：版本化视觉契约、变更日志、截图索引、可复制的下一版输入模板。

**出口**：新世界可只替换事实数据和资产 manifest 复用这套舞台；Viewer 能从 Skill + 世界目录重新构建。

## 4. 状态与截图回归矩阵

项目可扩展时间步，但最少覆盖下表。每格都保存截图和事实摘要：

| 状态 | 推荐时间步 | 必须可见 | 关键检查 |
| --- | --- | --- | --- |
| 世界总览 | T0 | 地图、世界栏、资源摘要、当前章节 | 地图占比、层级、首屏是否能读懂 |
| 移动 | 事件移动 tick | 路线、行走状态、抵达标记 | 角色在地面、路线不遮住关键文字 |
| 对话 | 对话 tick | 停步角色、气泡、对话底栏、来源 | 气泡不盖角色/面板、长文本换行 |
| 交换/决策 | 对应事件 tick | 参与者、资源 delta、事件高亮 | 数值与回放事实一致、焦点明确 |
| 收起面板 | 任一稳定 tick | 地图、标签、回放控件 | 不依赖永久打开的侧栏 |
| 窄屏 | 对话或移动 tick | 抽屉、地图、回放控件 | 无横向溢出、触控目标可达 |
| 缺失资产 | 任一 tick | 可读回退、诊断提示 | 不静默消失、不污染世界事实 |

每个截图文件命名为：

```text
{before|after}-{viewport}-t{tick}-{focus}.png
```

报告中的 `screenshots[]` 至少包含：`path`、`viewport`、`tick`、`focusMode`、`selectedId`、`commit`。

## 5. 自动与人工验收清单

### 自动检查

- 构建、world audit 和确定性 replay 通过；
- 页面无 JavaScript、资源、网络错误；
- Canvas 有非空绘制且地图/角色资产加载成功；
- 桌面/窄屏无水平溢出；
- 关键按钮和输入可聚焦，焦点状态可见；
- T0…Tn 的可见 tick、资源、事件 ID 与 replay frame 一致；
- 资产缺失触发 fallback 和诊断；
- offline 路径无模型、图片、音频或遥测请求。

### 人工复核

- 首屏三秒内能说出“发生了什么、关注谁、下一步做什么”；
- 地图是主角，默认没有统计卡墙；
- 角色有统一相机和尺度，脚底落在地面，阴影可信；
- 标签、气泡、路线、面板没有明显遮挡；
- 重要文本、长名字、大数字在桌面和窄屏都完整可读；
- 运行、暂停、回放、错误、空状态和 reduced-motion 都保持信息完整；
- 参考图只影响可执行的层级/材质/节奏，不复制具体品牌或受版权约束的内容。

## 6. 扩展与版本规则

1. **事实与投影分离**：新事件、新角色和新空间先进入世界 manifest/replay，再由舞台投影；不得在 CSS/Canvas 中写死规则。
2. **契约版本化**：改变相机、角色尺寸、断点、层级或 token 时递增 `style/layout` 版本；旧版工作区保持可重建。
3. **新增状态先扩矩阵**：任何新按钮、新面板或新事件类型，先增加状态/截图对，再实现 UI。
4. **资产可插拔**：通过 asset/animation manifest 接入新图片或帧动画；渲染器必须有稳定回退和哈希，不把 Provider 名称写进运行时。
5. **默认视图克制**：新增信息只能替换当前焦点或进入抽屉；不能把所有信息永久堆到地图上。
6. **响应式优先**：每个桌面组件都要声明窄屏行为（折叠、抽屉、滚动或隐藏），并在至少一个窄屏状态截图回归。
7. **动效不依赖**：动画只增强已经可读的状态；`prefers-reduced-motion` 下仍保留结果、文字和来源。
8. **对比必须可解释**：改版报告同时保留 before/after、运行 ID、提交和剩余风险；不以单张“最好看”的截图替代矩阵。
9. **外部模型不是前置**：Codex 可以完成契约、程序化场景、CSS/Canvas 和回归；Gemini/DeepSeek 等仅作为可选 Provider，不阻塞 Skill。
10. **发布前回滚点**：每次视觉大版本都保留上一版 viewer、契约和截图，失败时可切回而不改世界事实。
