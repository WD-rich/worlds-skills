# World Stage 大版本能力计划

这份计划把 World Stage 从“能显示回放”提升为“能承载叙事和视觉验收的游戏化舞台”。它只描述通用 Skill 能力；具体世界、素材、事件记录和截图必须写入调用方工作区。

## 新增能力

### 舞台 UI 导演

目录：`skills/stage-ui-director/SKILL.md`

输入：当前 viewer 截图、世界视觉契约、可见状态清单和目标视口。

输出：

- 布局契约和设计 token；
- UI 状态矩阵；
- 地图、聚焦面板、回放栏和反馈层的层级规则；
- 文字、焦点、安全区和响应式诊断；
- 可复核的改动报告。

硬规则：UI 不得重复实现世界规则；默认视图不能被统计卡和详情面板占满；面板、标签和气泡必须有明确的当前目的。

### 舞台视觉 QA

目录：`skills/stage-visual-qa/SKILL.md`

输入：构建后的 viewer、目标视口、时间步和交互状态清单。

输出：

- 固定运行 ID 的截图清单；
- DOM 状态和回放事实快照；
- 空白画布、资源错误、文字截断和重叠诊断；
- 人工视觉复核入口和残余风险。

硬规则：功能回放通过不等于视觉通过；每个 UI 质量结论都必须绑定具体视口、时间步和截图。

## 现有 Skill 的升级方向

### world-stage

- 从单一地图视图升级为世界、角色、事件三种聚焦模式；
- 统一 Canvas 投影、DOM 面板和键盘焦点；
- 支持状态矩阵和视觉 QA 清单；
- 保持 live、replay、sandbox 和 offline fallback。

### scene-painter

- 输出背景、结构、遮挡、角色、特效的分层场景；
- 为交互点、路线和重点区域提供稳定锚点；
- 对地图忙乱度、可读区域和缺图回退做审查。

### sprite-forger

- 输出脚底锚点、方向、动作、帧率和边界；
- 提供角色预览 gym，能够查看 idle、walk、talk、interact；
- 不因缺少图片而删除角色或改变运行事实。

### world-audit

- 校验视觉 manifest、锚点、动作引用和 fallback；
- 将视觉报告与回放哈希关联；
- 检查构建出的 viewer 是否仍是工作区的可重建派生物。

## 版本边界

本能力升级不要求 Gemini、DeepSeek 或其他外部模型。程序化地图、已有图片、CSS/Canvas 动效和 Codex 浏览器验收足以完成第一阶段。外部图像、3D 或视频生成以后只作为候选资产 Provider，不能成为 Skill 正常工作的必要条件。

## 实施顺序

1. 先添加 UI 导演和视觉 QA 的契约与报告格式；
2. 再让 world-stage 消费布局契约并提供聚焦模式；
3. 再让 scene-painter 和 sprite-forger 输出更完整的锚点、层级和动作清单；
4. 最后把截图矩阵和报告纳入 world-audit 的发布前检查。

## 质量出口

- 运行事实和视觉投影仍然分离；
- 缺失资产有稳定回退；
- 关键状态有目标视口截图；
- 视觉诊断能指出具体文件、组件、时间步和修复建议；
- Skill 仓库不携带任何具体世界的故事、图片、事件记录或私密 Provider 信息。
